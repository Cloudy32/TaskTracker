# TaskTracker — новый фронтенд

Отдельное React-приложение на основе `../todo-app-frontend`: русский интерфейс, тёмная палитра и золотые акценты. Сборка — Vite. Исходный фронтенд, `../main.py` и `../requirements.txt` не изменены.

## Запуск

Нужен Node.js 22.12 или новее. Из папки `frontend`:

```powershell
npm install
npm run dev
```

Открыть http://127.0.0.1:3000. Если используете pnpm, выполните `pnpm install --frozen-lockfile` и `pnpm dev`.

Бэкенд запускается отдельно вашим обычным способом. Его адрес задаётся в `.env`:

```dotenv
VITE_API_BASE_URL=http://localhost:8080
```

Если бэкенд работает на порту 8000, замените значение на `http://localhost:8000`. После изменения `.env` перезапустите фронтенд. В production значение фиксируется во время сборки, поэтому после изменения адреса нужна новая сборка.

## Прямое подключение — без прокси

Браузер отправляет запросы непосредственно на `VITE_API_BASE_URL`. Прокси, обход CORS и `mode: no-cors` не используются.

При запуске интерфейса и API на разных origin (в том числе на разных портах) браузер требует разрешения CORS со стороны сервера, в том числе успешного OPTIONS preflight для JSON POST, PATCH и DELETE. Сервер должен разрешать origin фронтенда, нужные методы и заголовок `Content-Type`. По просьбе пользователя бэкенд не изменяется, прокси не добавлен. Когда запрос заблокирован, приложение показывает ошибку и сохраняет введённый текст.

## Поддерживаемое API

| Операция | Запрос | Ответ |
| --- | --- | --- |
| Получить задачи | `GET /tasks` | Массив `{ id: string, title: string, completed: boolean }` |
| Добавить задачу | `POST /tasks`, JSON `{ "title": "Название" }` | Созданная задача той же структуры, HTTP 200 или 201 |
| Изменить задачу | `PATCH /tasks/{id}`, JSON `{ "id": "...", "title": "Название", "completed": true }` | Обновлённая задача той же структуры, HTTP 200 |
| Удалить задачу | `DELETE /tasks/{id}` без тела запроса | Успешный HTTP-статус, в том числе 204 без тела ответа |

Доступны создание по кнопке или Enter, поиск без учёта регистра, фильтры и счётчики. Фильтрация выполняется в браузере. Состояния загрузки, пустого списка, ошибки и успешного создания обрабатываются отдельно. Во время отправки повторное создание заблокировано.

У каждой задачи есть кнопки «Изменить» и «Удалить». Редактор позволяет поменять название и чекбокс «Задача выполнена», сохранить изменения или отменить их. Поле `completed` отправляется как JSON boolean (`true` / `false`), а не строка. `id` включён в тело PATCH для совместимости с `TaskSchema` в текущем бэкенде. Список и счётчики меняются только после успешного ответа сервера; при ошибке черновик редактирования сохраняется. Параллельные отправки и обновление списка во время операции заблокированы.

В текущем `main.py` реализованы обработчики задач GET, POST, PATCH и DELETE. Бэкенд в рамках изменений фронтенда не редактировался.

## Категории — отдельный CRUD

Откройте «Категории» в боковом меню. Список загружается при открытии раздела. Форма создания принимает название. Кнопка с карандашом открывает редактор, «Сохранить» сохраняет новое название, «Отмена» сбрасывает черновик. Кнопка с корзиной удаляет категорию. Раздел не запрашивает задачи и не хранит связи с ними.

В бэкенде на момент перехода к отдельному CRUD есть GET и POST категорий с полями `id` и `name`. Кнопки изменения и удаления подготовлены для PATCH и DELETE по контракту ниже; соответствующие обработчики нужно реализовать на сервере. Бэкенд не изменён. Прямое подключение по `VITE_API_BASE_URL` сохранено, прокси не используется.

Объект категории:

```json
{
  "id": "category-uuid",
  "name": "Работа"
}
```

| Операция | Запрос | Ответ |
| --- | --- | --- |
| Получить категории | `GET /categories` | HTTP 200, массив объектов категории |
| Создать категорию | `POST /categories`, JSON `{ "name": "Работа" }` | HTTP 200/201, созданная категория с `id` и `name` |
| Обновить категорию | `PATCH /categories/{id}`, JSON `{ "name": "Работа" }` | HTTP 200, обновлённый объект категории |
| Удалить категорию | `DELETE /categories/{id}` без тела | HTTP 204 без тела или другой успешный HTTP-статус |

В POST и PATCH передаётся только `name`. Ответы с `id` и `name` принимаются без дополнительных полей. При ошибке HTTP или некорректном ответе приложение сохраняет черновик и показывает ошибку; список меняется только после успешного ответа сервера.

Основной код раздела — `src/Categories.jsx`, сетевые методы — `src/api.js`, проверки — `src/test/Categories.test.jsx`.

Бэкенд хранит задачи в оперативной памяти. После его перезапуска список обнуляется; фронтенд не создаёт отдельное хранилище или демонстрационные задачи.

## Проверки и сборка

```powershell
npm test
npm run build
npm run preview
```

Сборка находится в `dist`. `preview` показывает сборку локально на порту 3000; сначала остановите `dev`, если он занимает этот порт. Для размещения `dist` используйте обычный статический хостинг с настроенным прямым доступом к API. Vite не является production-сервером.

Автоматические тесты используют подменённый `fetch` и проверяют контракт API и поведение интерфейса; они не подтверждают разрешение CORS у реально запущенного сервера.

Основные файлы: `src/App.jsx` — интерфейс, `src/api.js` — прямые запросы, `src/styles.css` — оформление и адаптивность, `vite.config.js` — сборка без прокси.
